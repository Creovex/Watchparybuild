# Writing rules

These rules apply to every file in this repository: code comments, commit messages, markdown, user interface copy and anything else someone writes here.

1. No version numbers in authored text unless James asks for one. Package versions live only in lockfiles and `package.json`. Version fields that a config file requires (`manifest.json`, `package.json`) are exempt.
2. Never put a dash between words where a comma, colon, semicolon or full stop belongs. Hyphens appear only inside real compound words (such as "peer to peer" written as one adjective, "full-stack"), file names, paths, code and technical strings.
3. No AI writing tells: no filler openers, no stock transitions, no symmetrical padding, no bolding of every other phrase. Name sections by what they contain.
4. Plain language. Define every acronym and technical term the first time it appears in a document.
5. Track gaps by name. If a gap exists, the item it affects is not done; it is reported as open, never hidden.
